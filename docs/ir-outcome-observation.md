# IR回答の情報価値を検証する観測設計

IRの返信を真の事業状態の代わりに使わず、質問時に固定した仮説と、その後に入手する公開資料を別々に記録する。現在は実測されたIR回答の精度・状態別尤度がないため、本書だけで `likelihoods` を埋めたり、自動送信・投資判断を有効にしたりしない。

## 採用根拠と本書の位置付け

情報価値の定義は、Baio・Heath・Manolopoulouの著者公開資料 [EVSI with the Moment Matching method](https://gianluca.statistica.it/research/voi/) に掲載された式を採用する。取得確認の証跡は [採用調査の保存資料](../research/ir-policy-adoption-2026-10-15/evidence/08a2f88e320ec50a.json) にある。

`EVSI = E_signal[max_action E_state|signal[payoff]] − max_action E_state[payoff]`

返信という信号と事業状態は別の変数であり、必要なのは `P(signal | state)` である。本リポジトリの [計算器](../src/ir_agent/information_value.py) はこの定義を有限状態の厳密な和で独立実装した。原著のmoment matchingアルゴリズムを実装したものではない。医療分野の具体的な費用・判断基準も採用していない。

仮説の事前記録、反証の追跡、変化の日時と影響の記録、材料の予定管理は、固定コミットで保存したAnthropicの [Thesis Tracker](../third_party/anthropic/skills/thesis-tracker/SKILL.md) を採用根拠とする。原文・取得時点・コミット・ライセンスは [manifest](../third_party/anthropic/manifest.json) に保存している。

以下の観測項目・紐付け・保留分類は、これらの原則を日本株のIR質問に適用するための本プロジェクトの設計である。外部資料で実証済みのIR予測手法や、既に稼働するデータ収集機能として扱わない。本書は保存項目の提案であり、既存CLIの入力契約を追加・変更しない。

## 最初に区別する三つの問い

| 問い | 観測する内容 | それだけでは分からない内容 |
|---|---|---|
| その企業は返信するか | 到達確認、返信・拒否・期限内無回答、返信までの時間 | 返信が事業状態を識別する精度 |
| 返信は仮説を識別するか | 事前状態、返信分類、独立した後続公開証拠 | 投資家が実行できる超過収益 |
| 判断改善に役立つか | 公開情報だけの判断と返信を加えた判断、費用、実行可能な価格 | IRが株価変動を引き起こしたという因果関係 |

返信率は `P(reply)` であり、計算器が要求する状態別の `P(signal | state)` ではない。株価上昇や運用損益も、質問時の「一時費用か恒常費用か」の正解ラベルにはしない。好意的な文章や担当者への印象を状態の正解にしない。

## 質問前に固定する観測単位

観測単位は原則として「会社×質問×事前に定義した論点×判定期限」の一件とする。同じ会社への再質問や返信の追伸は、元の観測と紐付け、独立した成功件数として増やさない。複数の論点を混ぜた質問は、論点ごとの状態・信号の関係を定義できるか先に確認する。

| 項目 | 固定・保存する内容 |
|---|---|
| 識別子 | 証券コード、会社ID、質問ID、仮説版、policy ID・版、観測設計の版 |
| 判断時点 | 質問作成時刻、利用可能な公開資料、出典ID、原文・ページ、初回取得時刻 |
| 対象状態 | 相互排他的で全体を覆うstate一覧、対象期間、会計範囲・単位、状態の判定規則 |
| 状態の意味 | 質問時に既に存在する未確認の状態か、将来の結果かを明記。両者を同じstateにしない |
| 事前確率 | 明示prior、根拠、外部事実と利用者の仮定の区別。実測値がないときは推定値を作らない |
| 信号 | 相互排他的な返信分類と符号化規約。曖昧・回答拒否・期限内無回答を含む |
| 送信状況 | 未送信・送信済み・到達不明・到達失敗を区別。実際の外部送信確認と時刻 |
| 二つの期限 | 返信待ち期限と、公開資料による状態の判定期限。それぞれ日付・時刻・タイムゾーン |
| 検証資料 | どの決算・公開説明・実績資料のどの項目で検証するか。開示されない場合の保留条件 |
| 判断の関係 | state/action別payoff、費用と共通単位、回答別の変更可能なモデル入力、反証条件 |
| 選定理由 | 質問対象にした理由、対象候補なのに質問しなかった理由、既存の重複質問 |

状態を「一時費用」と「恒常費用」にする場合、同じ費用に双方が混在する可能性を定義から落とさない。混在状態を追加するか、公開資料から判別できないケースの扱いを先に固定する。混在を後から都合のよい状態へ押し込まない。具体的な金額・比率・最低件数の閾値は、この設計では設定しない。

## 返信は原文と分類を分ける

原文、受信時刻、質問との対応、利用条件、情報の公開性を保存する。返信の分類は事前の符号化規約で行い、引用箇所と分類理由を残す。分類に迷えば曖昧な信号として扱い、回答内容を見てからsignal一覧や状態の定義を変更しない。

返信待ち期限までの無回答を一つの信号として定義した場合、その期限後の返信は「遅延返信」として別に保存する。当初の期限時点の信号を返信ありへ上書きしない。到達失敗は企業の無回答と区別する。通信障害・受付休止・送信未実施を企業の事業状態と結び付けない。

公開性が不明な返信と、公開情報の補足と確認できた返信を区別する。観測研究への利用が可能か未確認の内容は、利用・共有を保留する。その場合も、観測対象から黙って削除せず、内容を使わない保留理由を記録する。

## 後の公開資料から状態を判定する

状態の判定は、返信の評価とは別工程にする。判定担当へ渡す資料は、事前の状態定義・対象期間・判定規則・期限と、後から公表された公開資料である。可能な範囲で、返信分類・IR後の売買判断・その後の投資成績を見せずに判定する。後続資料の引用、公開日時、取得日時、対象期間、判定者、判定時刻、状態の判定結果と理由を残す。

公開資料にも状態を確定できるだけの内訳がない場合がある。経営者の説明を、独立して確認された会計実績と同一視しない。判定結果は、少なくとも次の違いを保持する。

- `verified`：事前の判定規則を満たす公開証拠が得られた。
- `pending`：予定した公開資料・判定期限がまだ到来していない。
- `not_identifiable`：期限を迎えても必要な内訳が公表されず、状態を識別できない。
- `state_changed`：外部事象等で状態が変化し、後の結果から質問時の状態を判定できない。
- `definition_mismatch`：定義・会計範囲・対象期間が合わず、同じ問いとして照合できない。

これらは観測設計上の分類案であり、現行DBの列挙値ではない。保留・識別不能を不正解に数えない。判定期限を延ばす場合は新しい版と理由を追加し、元の期限・期限時点の結果を残す。

例えば質問後の買収、価格改定、為替・原料価格変化、制度変更、事業撤退、会計区分変更が利益率を変えたときは、その発生日と影響を記録する。将来の利益率だけを見て質問時の費用の性質を逆算しない。質問時の状態 `state(t0)` と、その後の実績 `outcome(t1)` の関係を説明できなければ、状態別尤度の学習には使わない。

## 尤度を校正する前の集計

返信のある企業だけを集めず、事前に登録した対象、質問候補、実際に送信した対象、到達失敗、無回答、状態の未判定を追跡する。送信率・到達率・期限内返信率・状態判定可能率は別の分母で報告し、どの段階で対象が減ったか明示する。

状態を独立して判定できた標本については、`state × signal` の度数表を作れる。`n(state, signal) / n(state)` は、その**判定できた標本内**の記述的な比率である。母集団の `P(signal | state)` と同一だと断定しない。あるstateの件数がゼロなら、その列の尤度は未校正のままにする。観測ゼロのsignalを不可能と断定したり、任意の擬似件数を足したりしない。

特に次の選択の偏りを記録する。

| 偏りの経路 | 保存する情報・分けて確認する観点 |
|---|---|
| 問い合わせ先が見つかる企業だけを選ぶ | 窓口確認状況、個人受付条件、業種・規模による対象の違い |
| 良さそうな仮説の企業だけに質問する | 質問候補の母集団、質問前の評価・選定理由、未送信理由 |
| 回答しやすい論点だけ返信される | 論点・質問形式、沈黙期間、公開情報の充実度、拒否・無回答 |
| 状態を後で確認できる企業だけ残る | 判定可能率、開示の細かさ、識別不能と対象除外の理由 |
| 同じ会社の多数の質問を独立件数にする | 会社ID、連続する質問、共通の決算・担当者・対象期間 |
| 方針変更や環境変化を無視して全期間を混ぜる | 質問・分類規約の版、送信時期、受付方針や事業の変更 |

少数の都合のよい返信事例から、全企業・全論点共通の「IR正答率」を作らない。状態の正解が観測できる確率も企業や返信に依存し得るため、判定可能な標本への限定自体が偏りになる。その偏りを解消できなければ、適用可能範囲を限定するか未校正のままにする。

## 未使用データで確かめてから計算器へ渡す

推定手順、事前分布・平滑化の有無、不確実性の扱い、適用対象、評価方法は、別途公開された統計手順を選び、根拠を保存してから採用する。本書では最小標本数、擬似件数、信頼度、採用スコアの既定値を置かない。

同じ会社・同じ決算・同じ返信の断片が推定用と評価用の双方に入らないようにする。時間の順序も保ち、後の資料から作った尤度で過去の質問価値を当時計算できたように扱わない。評価対象への適用時点より前に利用可能だったモデル版・データ範囲を固定する。

評価では状態別・論点別の観測数、未判定の割合、予測した信号分布と実際の信号の対応、モデルの不確実性と適用限界を示す。尤度は複数のsignalの確率分布なので、単一の「正答率」だけに縮約しない。性能の評価方法と合格基準は、結果を見てから選ばず、根拠のある手順を先に決める。

その結果、当該質問に適用できる尤度の根拠が整って初めて、`information-value` の入力に版を付けて渡す。入力provenanceには、観測コホート、対象会社・期間、状態の判定方法、推定方法、評価結果、残る仮定を紐付ける。保存された外部証拠と、まだ検証されていない利用者の仮定を区別する。

整わなければ `likelihoods` を省略し、計算器は `needs_calibration` とEVPIの上限だけを返す。EVPIが大きいことを、IR返信のEVSIが大きい根拠にしない。

## 投資成績の検証は別の記録にする

質問前の公開情報のみの判断、返信後の判断、実際に行った判断を区別する。仮説版、評価入力、相場の出典と時刻、費用、検証期限を紐付ける。質問の回答分岐に当てはまったことと、最新価格・リスク条件を満たしたことも区別する。

IRを利用した戦略の成績を評価する場合は、送信対象全体と無回答も含め、同じ時点・同じ価格利用条件で公開情報だけの基準と比較する。収益・損失が為替、相場全体、別の開示、事前の銘柄選択等から生じた可能性を残す。実際の売買を行わず判断を記録する場合は、仮想的な成績と明記する。

対話の効果に関する[Solomon・Soltesの書誌と登録要旨](../research/ir-private-investor-meetings-paper-discovery-2026-10-15/README.md)も確認した。2011年SSRN登録の要旨は、NYSE上場1社の個別面談と投資家の取引タイミング、その効果の参加者差や情報環境との関係を報告する。掲載版本文は[取得停止](../research/ir-private-investor-meetings-journal-source-2026-10-15/README.md)で未読、要旨と掲載版の同一性・方法・因果識別は未検証である。この登録要旨から日本の個人向けメール/フォームIRの効果、返信尤度、必要な質問頻度を設定しない。対話が追加したものを公開情報だけの判断と比較する、という本プロジェクトの検証課題として残す。

実返信の観測データはまだ揃っていない。本書の完成は、IRの予測力、超過収益、送信実績、尤度の校正が確認されたことを意味しない。
