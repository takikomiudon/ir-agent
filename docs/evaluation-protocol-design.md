# IR信号・独立stateの評価手順を事前固定する最小設計

全体は設計メモ。Aのrecord-only protocol registryだけを接続した。BのpacketとCの判定記録は未実装。対象は、原文bindingの機械点検の次に必要な「評価手順とラベル判定の来歴」である。新しい原典GETは行っていない。新しい確率、数値閾値、標本数、重み、実企業のstate、IR送信案は作らない。

結論：最小の次の追加は、(1)不変のevaluation protocol、(2)stateとsignalで異なる入力packetの内容固定、(3)そのpacketと手順に結び付く追記型の判定記録である。source-bindingのmatchedをまとめて採点可能へ昇格するフラグは追加しない。ここでのAPI・schema案とblind運用は本プロジェクトの適応で、原典が示した完成済みIR実験手順ではない。

## 追加する記録を三つに限定する

### A. evaluation protocolの不変版

新しい投資policyを作るのではなく、既存の観測・予測をどう評価するかを固定する独立した記録とする。最低限の項目は次のとおり。

| 項目 | 固定する内容 |
|---|---|
| 識別 | protocol ID・版、内容SHA、記録者、recorded_at、trusted first_saved_at。旧版を上書きしない。 |
| 評価課題 | `P(signal|state)`の前向き評価か、別の課題か。IR追加価値、売買損益、`P(state|signal)`を同じ課題にしない。 |
| 対象 | 既存cohort/design/定義SHA、state_timing、対象期間、質問型、synthetic区分、対象観測の組入れ規則と時点。投資窓口台帳全社を自動的な評価母集団にしない。 |
| 対象モデル | 比較するモデルID/版と予測の選択規則。結果を見て勝った予測だけを採用しない。 |
| state判定規則 | 既存stateの意味と相互排他性、何を観測したらどのstateか、どの資料種別・指標・期・範囲・単位を使うか、不識別・混在・矛盾・外部変化時の保留条件。 |
| signal分類規則 | 既存signalsと定義、対象返信の選択、引用をどの規則へ対応させるか、複数該当・矛盾・拒否・曖昧の扱い。肯定語や語調だけの分類にしない。 |
| packet分離 | state担当・signal担当に渡してよい情報と除く情報、packet生成手順の版、分類を固定するタイミング、露出が不明な場合の扱い。 |
| 無回答 | 対象窓口・受信経路・期限・受信確認範囲と証跡、送達不明/ログ不完全/未送信を無回答にしない規則。 |
| 訂正 | 元分類と訂正版、state判明後のsignal変更を主評価へ自動差替えしない規則、事後感度分析の区別、公開性取消の現在保留。 |
| 分割・比較 | 学習情報の利用可能締切、企業/決算/質問group、一般化対象、評価期間と未使用対象、異定義・異期間・欠測を混ぜない規則。 |
| 出力 | 母集団の全件、未予測・未送信・未観測・未判定・保留、採用した観測版と判定来歴。合否スコアや未設定重みは置かない。 |

未来の公開資料のIDやSHAは、存在する前には固定できない。先に固定するのは「どの資料・表・期間を選ぶか」という選択規則であり、後から見つかった実資料のID・版・SHAを判定記録に結ぶ。既知の会社予想を比較の基準に使う場合、その基準資料・版・数値・期・定義は予測前に固定する。後の改定予想を当初基準へ置換しない。

必要な定義が欠けたprotocolはdraftとして保存できても、前向き評価の採用規約として解放しない。採用者を名乗ることや追加の利用者承認を、保存済み公開資料の整理など全作業の停止理由にしない。

### B. 判定用packetの内容commitment

最低限、packet ID、protocol参照、対象観測ID/設計SHA、役割、全入力snapshotのID/版/SHA、生成コード/設定版、生成時刻、trusted保存時刻、除外した情報の種類を保存する。入力の内容を解決できずhash文字列だけある場合はpacketの再現を確認済みにしない。

| packet | 渡す情報 | 原則として渡さない情報 |
|---|---|---|
| state判定用 | 事前state定義と対象期間、事前の比較基準、選択規則に合う後続公開資料、財務ラベル/表位置、外部変化の証拠。 | 対象IR返信の原文・signal、予測確率、モデルの事後確率、売買判断、損益、他担当のstate結論。 |
| signal分類用 | 質問の原文・参照定義、事前signals、既存規則で選んだ返信原文、受信・期限情報、分類に必要な公開定義。 | 後から判明したstateや実績、予測確率とモデル評価、売買判断・損益、state担当の結論。 |

同じworkspaceや親の全履歴を受け取った担当者を、名前を分けただけでblindとしない。LLMを使う場合、親履歴や後続stateを渡さない新しい文脈、渡したtool出力、アクセスできた資料を記録する必要がある。実際のアクセス制限がなければ「入力packetには含めていない」という狭い事実に留め、他経路で知らなかったことまで証明しない。

`independent:true`、`blind:true`、担当者の役職や自己申告は判定根拠の代わりにならない。packetの範囲、元資料の来歴、実行/閲覧記録、時点、未確認の露出を具体的に返す。

### C. 追記型の判定記録

判定記録はID/連番版、対象観測と使用snapshot、protocol版、packet参照と内容SHA、担当・実行器、実行コード/設定版、recorded_at/trusted first_saved_atを持つ。stateなら判定stateまたはnullと保留理由、signalなら元/採用カテゴリ、規則ID、必要な全根拠・引用・計算入力・途中結果を保持する。

新しいsource-binding reportを根拠参照として結び、文字列・来歴・時点・公開性の確認結果と、規則が状態やカテゴリを支持する意味上の理由を別々に記録する。参照が実在しただけで意味レビューをtrueにしない。

再判定は次版へ追記し、元の本文、観測、protocol、予測、判定記録を変更しない。期待直前版のCAS、要求同一の冪等再送、実保存時刻、外側transactionのrollbackを既存の記録原則に揃える。訂正を独立した観測件数へ増やさない。

## 結果を見る前の時点と、判明後の訂正

protocolのtrusted保存を、対象の組入れ・予測・送信より前に置く前向き手順とする。少なくとも、元の観測設計・予測・protocolが受信や結果判明後に作られたものを前向き登録としない。既に受信・state判明済みの実データへ新protocolを後付けした場合は、遡及的な開発/感度分析であることを残す。

signal固定とstateの判明は、単一の申告日時だけでなく次を分けて記録する。

- 予測生成・実保存、実送信、実受信、返信のDB実保存、対象返信を選んだ時点。
- signal packet生成・実保存、分類開始・記録・実保存、対象訂正版の生成・根拠利用可能時刻。
- state根拠の公表、取得、当時利用可能性の証跡、state packet生成、状態判定と実保存。
- 後の訂正が見えるas-ofと、現在のtrusted点検時刻。

state公表後にsignalを再分類した場合、引用や分類理由が整っていても主評価を自動更新しない。stateにアクセスした可能性、事前packet手順、訂正採用規約を点検し、不明なら主評価利用は保留する。現在の記述的集計には訂正viewを使えても、予測検証への採用と同一ではない。元の分類へ自動的に戻して問題を迂回することもしない。

訂正後の計算を必要とする場合は、採用された主評価と区別した事後の感度分析として版付きで残す。lossが改善したことを分類訂正の採用理由にしない。過去の早いrecorded_atを自己申告しても、実保存前の証跡にならない。

## 企業公表値を使うrule-basedなstate確認の範囲

現在の[公表値索引](../research/ir-case-studies-2026-10-15/disclosed-fact-index-v2.json)には、IIJ・パイオラックス・千葉銀行・日本冶金工業の公表値が整理されている。元資料・引用・単位変換の再現と、`reported_fact / issuer_guidance / general_explanation`の区別は有用だが、[normalizer](../src/ir_agent/disclosed_facts.py)は明示的に意味のレビューを残している。period/scope/definition/表列はレビュー上の主張であり、正規化成功をstate判定済みとしない。

### 最小の規則処理

最初の規則処理は、限定した公表事実に対する純粋な照合に留める。

1. 事前に固定した状態の意味と、evidence選択規則を解決する。
2. 全原典が循環せず、対象IR返信の転載/要約/派生ではなく、対象の公表計算書や表へ結び付くことを点検する。資料IDやURLだけの違いを独立性にしない。
3. 同じ会社、概念、実績/予想の区分、対象期、連結範囲、会計基準、単位、表列、EPSならbasic/dilutedと株数基準を照合する。明示単位変換だけを再現し、期間換算・年率化・利益の正常化を自動で行わない。
4. protocolが元々定めていた比較や判定式だけを、結合したfactと固定基準へ適用する。新しい数値基準や、都合のよい比較演算子を結果後に作らない。
5. 規則に必要な内訳がない、混在する、資料が矛盾する、期間や範囲が違う場合はstate:null。計算できたことと経済的な因果説明が正しいことを分ける。

ここで確認できるのは「その企業がこの範囲・期の値を公表した」「事前規則のもとで、この公表値と固定基準の関係が成立する」という限定された事実である。同じ発行体の別財務資料はIR返信とは別の観測経路になり得るが、発行体から統計的に独立した測定や経済的真実の保証ではない。監査報告書の存在も、当プロジェクトが監査を再実施したという意味にはならない。

比較の基準を会社予想にする場合、数値の出所が会社であることと、その比較を評価stateとして採用した事前protocolの根拠は別である。実際の分類・演算子はここでは採用しない。現在の資料群には実返信と独立stateの前向き観測が揃ったわけではなく、新しい実企業ラベルを出力しない。

欠損記号、未確認dash、数値なし、定義の混在は0にしない。IR返信と同内容を後の公開Q&Aへ転載したものは、公開性の確認に役立っても、その返信を検証する独立した状態実現の根拠にはならない。

## 外部変化と質問時state

`state_timing: at_question` と `future_outcome`を区別する。将来の公表実績に対する規則が実行できても、それを質問時の状態へ遡って適用できるとは限らない。買収・会計区分変更・価格改定・為替/原材料・制度変更などが間にある場合、発生日と影響、対象期間・範囲の連続性を点検する。

一件を `reviewed_no_change` にしたことだけでstateをverifiedにしない。他の未解決事象を保持し、質問時stateを識別できなければstate_changed/not_identifiable/definition_mismatch等の既存観測区分へ保留する。状態の変化と、当初の予測が誤ったことを同じラベルへ押し込まない。

## 無回答のsignalを固定するための記録

無回答には引用する返信がない。元の実送信・宛先・受付条件・送達状況、登録した受信経路、返信待ち期限、期限まで確認した受信ログの内容commitment、確認範囲と欠損、確認者・時刻・実保存を参照する。単独の `checked_through` 自己申告を完全ログの独立確認にしない。

採用できる意味は、事前に登録した経路の確認範囲で「期限内返信を観測しなかった」というものに限る。会社が他経路でも一切返信しなかった、事業状態が悪い、とはしない。未送信・送達不明・ログ欠落・期限前は無回答と別に残す。期限後返信は元の期限内無回答を上書きせず遅延イベントとして保持する。

## 機械source-binding後に実装するなら最小の順序

1. protocolの厳格な入力検証と不変登録・版・実保存時刻・SHA。観測、予測、投資policyへ影響しない独立registryにする。
2. 既存観測版とsource-binding reportを読むpacket builderを追加し、役割別の入力集合と欠損/保留をread-onlyに出力する。最初は実レビューやscorerを自動起動しない。
3. 固定protocol/packetに結び付く判定記録を追記する。限定した公表値照合規則で再現できる判断と、意味解釈/露出が不明な判断を分ける。自己申告の独立true欄を設けない。
4. 元分類・訂正・state判明時点・学習来歴をまとめた評価候補レポートを作る。全観測を左結合で保持する。この段階でも既定の `score_request:null` を勝手に解放しない。

採点を前向き検証として採用する後段は、実際に不足が解消したことを別途点検してから設計する。確率の生成、尤度学習、重み付け集計、投資成績比較、IRの追加価値の主張はこの有限追加に含めない。

## 未解決事項

- どの質問型が公開資料から状態を識別できるか。費用の一時性等は、原典に必要内訳がないと判別できない。
- signalの意味判定を機械式にできる範囲、混在・否定・限定回答を扱う手順。単語の出現だけでは十分でない。
- 実際のblind運用のアクセス制御・閲覧履歴・担当間の情報共有。packetのhashだけで担当の知識を完全に証明できない。
- state根拠が同じ発行体に依存すること、誤表示/訂正の扱い、公開性の取消と再点検。
- 同社・同決算・同担当・同論点、親子会社/業界要因のgroupと時間分割の具体化。無根拠の独立標本数や有意差は出せない。
- 不送信・無回答・識別不能の選択による偏り。完成した標本だけで全母集団へ一般化できない。
- 未公表の将来資料の選択規則と実資料の結合、予想改定・訂正再表示の採用規則。
- 実state、実signal、実測尤度が未収集であること。この設計だけで前向き評価を完了できない。

## 実装受入条件

| 条件 | 必要な結果 |
|---|---|
| protocolを受信後/state判明後に登録、recorded_atだけ過去 | 前向き登録としない。実保存時刻を保持し、遡及的な分析として区別。 |
| 同protocol ID/版へ内容変更、状態定義・期限の後付け | 拒否。新しい版と将来対象へ適用し、過去観測を再登録しない。 |
| signal packetへstate資料/予測確率/損益が混入 | packet契約違反または露出不明を報告し、blind保証や主評価採用へ進めない。 |
| state packetの原典が対象IRの派生・転載 | 来歴の非循環確認に失敗。公開性の確認と独立stateを分け、stateは保留。 |
| 引用/token/SHAは一致、kind/表列/期間/範囲の対応が未確認 | 機械bindingだけmatched。stateや意味レビューを確認済みにしない。 |
| 四半期と通期、単体と連結、basic/diluted EPS、実績と予想の混同 | 規則評価を行わずmismatch/unknown、欠損や将来値を補完しない。 |
| 事前の同期間・同概念の固定比較を、完全な根拠で再現 | 公表値関係の限定された規則結果と全入力/途中結果を返す。経済的独立・収益性・校正へ昇格しない。 |
| 独立true/承認trueだけを入力、参照や実際の露出記録なし | 未定義field拒否またはunknown。自己申告を検証結果へ置換しない。 |
| state判明後のsignal訂正でlossが改善 | 元分類/訂正版/時点を保持し、主評価へ自動採用しない。事後感度分析を分離。 |
| 一つの外部変化は整理、別の影響やstate未確認が残る | 当該保留を維持し、verified stateを作らない。 |
| 受信確認の主張だけ、ログなし・期限前・未送信 | 無回答signalにせず、元対象と不足理由を残す。 |
| 同社複数質問、訂正版複数、未予測・未判定が混在 | 観測IDの一意性を維持し、全対象と理由を残す。独立標本数や0点を作らない。 |
| 新判定の途中でエラー、外側transactionがrollback | protocol/packet/判定が片方だけ成功した形で残らず、旧版を変更しない。 |

このメモは将来の最小追加と不足を示したもので、実装・実観測判定・前向き採点の完了報告ではない。


## 接続したrecord-only registry

```bash
.venv/bin/ir-agent --db PATH evaluation-protocol register FILE --expected-previous-version 0
.venv/bin/ir-agent --db PATH evaluation-protocol show PROTOCOL_ID --version 1
.venv/bin/ir-agent --db PATH evaluation-protocol history PROTOCOL_ID
```

`show`のversion省略時は保存済み最新版。新規v1は期待直前版0、v2は1を指定する。同じID/版/要求の再送は元の期待値で同じ記録を返し、後続版があっても元first_saved_atを保持。違う内容へ書き換えず、修正は次版を登録する。

[未設定template](../examples/evaluation-protocol.template.json)はid/recorded_at/recorded_byがnullなのでそのまま登録できない。識別と主張記録時刻・記録者を明示すれば、未設定規則をdraftとして保存できる。rulesはinclusion/state/signal/information_separation/no_response/external_change/correction/group_time/prediction_selection/population_outputの固定キーで、各値は手順文またはnull。実行可能なルールエンジンではない。

cohortはnullまたはid/design_version/definition_sha256/state_timing/target_period/question_type/states/signals/syntheticを持つ。target_periodはnullまたはstart/endの日付範囲、states/signalsはnullまたは名前→定義。model_refsはid/version/commitment_sha256/training_information_cutoff、source_refsはsource_id/content_sha256/quote_ids/purposeの配列。これらは宣言であり、既存DBへの実在・意味・著者原則採用を解決していない。

statusは`protocol_commitment_only`、空欄は`draft`/`unset_fields`へ残す。draft=falseでも完成度・前向き性・採点適格を確認したことにはならない。参照/引用/原則採用/規則/前向き性/盲検/独立性はunverified、executionはnot_performed、score_eligibilityはnot_assessed。JSONへtrusted first_saved_atや承認booleanを指定できない。過去のrecorded_atだけで事前登録へ昇格しない。

SQL tableはir_evaluation_protocol_versions。trusted保存時刻とSHAを元要求とともに保持し、同tx/savepoint・CASを守る。statusのevaluation_protocol_versionsは保存版数で、検証済み方針数ではない。全1,154テスト成功、独立再確認と実スキーマ移行の結果は[チェックポイント](../research/ir-evaluation-protocol-integration-2026-10-15/README.md)に保存した。
