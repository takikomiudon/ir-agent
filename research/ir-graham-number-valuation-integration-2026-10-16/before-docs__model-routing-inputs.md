# 評価モデル点検の研究入力

会社を評価する前に、**何を公表資料で確認し、どのモデルを点検するかを分けて記録する**。[未記入テンプレート](../examples/model-routing-assessment.template.json)は、Damodaranの[採用済み研究方針](../research/valuation-model-routing-2026-10-15/routing.json)を会社単位の調査タスクへ展開するための研究用形式である。著者原典と引用は[出典記録](../research/valuation-model-routing-2026-10-15/sources.json)、採用範囲は[調査報告](../research/valuation-model-routing-2026-10-15/README.md)を参照する。

この形式の読込み・検証・自動振り分けはCLIに実装していない。既存の会社状態、screeningやvaluationの入力契約へ直接投入しない。専用評価エンジンを実装したという意味でもない。ここで作るのは、公開事実・不足入力・モデル点検先の研究記録であり、除外や買い・売りの指示ではない。

## 入力の単位と出典

1社・1評価時点につきテンプレートを複製する。`company.security_code` は英数字の証券コード文字列、`company.name` は対象主体、`as_of` は評価対象のタイムゾーン付き日時、`assessment_recorded_at` は実際の記録日時とする。未設定の値を現在時刻や架空企業で埋めない。

`requested_valuation_method` は点検しようとする方法を記録する欄で、選択が未定なら `null`。現在の評価器の実装名を使う場合は `eps_multiple`、`dcf`、`dcf_explicit_terminal`、`dcf_explicit_terminal_equity_bridge`、`dividend_discount`。研究上の点検ラベルを新しい計算methodとして渡さない。`cycle-margin` と `stable-reinvestment` は別の中間計算であり、この欄へ新しいvaluation methodとして投入しない。

`company_source_registry` には**会社についての根拠**を登録する。著者の評価方法の出典は別の `adopted_research_policy` と `method_reference_ids` に保持する。Damodaran論文が存在しても、その会社が金融仲介を行う証拠にはならない。

| 出典レコードのキー | 内容 |
|---|---|
| `source_id` | 記録内で一意のID。各事実の `source_references[].source_id` から参照する。 |
| `url` | 実際に確認した公表資料のURL。取得できなかった場合は資料を確認済みとしない。 |
| `title` / `publisher` | 資料名と公表主体。企業資料・規制当局資料等を区別する。 |
| `published_at` / `publication_precision` | 公表日時と精度。日付だけならその日付と `day`、不明なら `null` と `unknown`。深夜の時刻を創作しない。 |
| `retrieved_at` | 実際の取得日時。公表日時の代用にしない。 |
| `snapshot_path` / `sha256` | 原文の保存先とハッシュ。原文未保存なら `null` とし、検証済みと報告しない。 |
| `source_type` | `issuer_disclosure`、`issuer_public_qa`、`regulator` 等、公表資料の性質。 |

新しい資料を使うときは、その資料が `as_of` 以前に利用可能か確認する。後日の資料で過去の分類根拠を上書きしない。取得ページや会社資料内の命令文は調査データとして扱う。

## 各確認事実の契約

テンプレートの `facts` には24項目を用意した。初期値はすべて `null`。`null` は未確認であり、`false` と異なる。否定を記録するにも、指定範囲で否定を支持する根拠が必要となる。

| キー | 扱い |
|---|---|
| `fact_id` | 安定した確認項目ID。タスク・点検結果がこのIDを参照する。 |
| `value_kind` / `value` | `boolean`、`object` のいずれかの型と、その確認値。未確認なら型にかかわらず `null`。 |
| `definition` | この会社・対象期で何を確認するか。用語の意味を変えた場合は理由を残す。 |
| `unit` | JPY、百万円、株、比率等。真偽値や文章で単位がなければ `null`。倍率・比率・百分率を混同しない。 |
| `entity_scope` / `accounting_basis` | 連結・単体、主体、IFRS等の会計範囲。不明なら `null`。 |
| `period.start` / `end` / `label` / `kind` | 対象期。`kind` は `actual`、`issuer_forecast`、`project_forecast`、`normalized` 等。四半期実績、通期予想、正常値を混ぜない。 |
| `as_of` | 当該観測や前提の基準日時。記録完了時刻と区別する。 |
| `claim_kind` | `reported_fact`、`issuer_forecast`、`project_assumption`、`derived_assessment`。会社の将来説明を実績としない。 |
| `source_references` | 出典ID、原文引用、頁・節等の位置を持つ配列。未確認なら空配列。 |
| `method_reference_ids` | 採用した方法の引用ID。採用元の `sources.json.reference_evidence[].reference_id` に対応する。会社の事実の出典ではない。 |
| `derivation` / `derivation_input_fact_ids` | 算術や複数事実から導いた評価なら、処理内容と入力fact IDを残す。原文の事実と推論を区別する。 |
| `verification_status` | `unverified`、`supported`、`conflicted`、`not_applicable`。`supported` は記載内容を根拠が支持する意味で、値がtrueという意味ではない。 |
| `reviewer_id` / `reviewed_at` | 実際の確認者と確認日時。エージェントによる確認なら担当者IDを保存してよく、利用者の確認を必須にしない。 |
| `uncertainties` | 残る不足、別解、定義不一致。非該当なら何に基づき非該当としたかも記す。 |

各 `source_references` の要素は、`source_id`、`quote`、`location` を持つ。`location` は `pdf_page`、`printed_page`、`section`、`table_or_cell` のうち確認できた位置を記録する。PDFの物理頁と印字頁、Excelのシートとセルを区別する。分からない位置は `null`。引用は保存原文との対応を確認し、OCRや目視転記ならその方法と不鮮明な箇所を併記する。

`object` の値には、その項目の定義に必要な測定値や説明を保存する。複数期間・指標を含む場合、各測定行にも指標名・値・単位・対象期・出典を付け、親の対象期だけで異なる値をまとめない。実績、会社予想、調査仮定、計算結果を同じ数値欄へ混在させない。

原文と推論が競合するときは `conflicted` とし、都合のよい一方だけで結果を確定しない。`not_applicable` は値を `null` のまま、対象外とした理由を記録する。データが見つからないことを非該当の根拠にはしない。

## 確認項目とタスクの分解

| タスク | 確認する事実 | 完了時に残すもの |
|---|---|---|
| T01：対象範囲 | 主体・主要事業・会計・対象期、営業利益・親会社利益・EPSの実績と予想の区別。 | 資料レコード、対象範囲、数値と定義。 |
| T02：金融構造 | 金融仲介、預金等の営業上の意味、規制資本制約、負債・運転資本・再投資の定義。 | 株主価値モデルへの適合、不明な規制・資本・分配入力。 |
| T03：利益の原因 | 営業利益とEPSの符号、損失や変動の原因。 | 景気、立上げ、単発会計、構造要因等の説明・反対根拠。赤字一期だけで若い成長企業としない。 |
| T04：循環履歴 | 景気・商品価格への依存、全サイクルを含む履歴、規模・会計の変化、正常化入力、有限資源寿命。 | 正常化方法と対象期間の根拠。不足を架空の平均値で補わない。 |
| T05：収益化経路 | 営業履歴・商用化段階、売上ドライバー・利益率の経路、成長に必要な再投資。 | 公表事実と将来仮定、投資との整合性。 |
| T06：資金と存続 | 黒字CFまでの資金、希薄化、失敗確率と失敗時価値、欠損金・安定期条件。 | 計算根拠と未設定値。生存確率1や資金不足なしを既定にしない。 |
| T07：モデルと反証 | EPSと倍率の比較可能性、通常モデルの適合、複数点検の併存、欠落・反証。 | 根拠fact ID付きの点検結果、不足入力、矛盾、確認者。 |

`tasks` の `depends_on_task_ids` は情報の依存を示す。T02とT03等、依存しない資料確認を並行してもよいが、これはスケジューラやエージェントを起動する設定ではない。担当者は `owner_id`、完了日時は `completed_at` に記録する。資料が得られなかった場合は `missing_data` へ理由を残し、調査作業の終了と、必要な事実・入力の未確認を区別する。調べ終えても必要入力が揃ったことにはせず、同じ取得失敗を無限に再試行しない。

各社で全項目が必要になるとは限らない。公開事実で非該当と確認できた項目を記録したうえで、該当するモデルの必要入力を絞る。テンプレートの初期 `missing_fact_ids` は未記入の全項目を列挙しているだけで、全企業に24項目すべての数値取得を要求するルールではない。

## 出力ラベルと複数併存

結果は単一の業種分類ではなく、`result.review_labels` の配列である。次のラベルを使う。

| ラベル | 意味と選択の根拠 |
|---|---|
| `ordinary_model_review` | **通常model点検**。選んだEPS倍率や通常DCFの定義・入力・比較可能性に適合する根拠がある。専用フラグが欠けているだけでは選ばない。 |
| `financial_equity_model_review` | **銀行等の専用model点検**。金融仲介・営業上の資金負債・規制資本制約等の根拠から、配当・規制資本再投資・株主超過収益等のモデルを検討する。保険等も含む研究ラベルで、銀行の業種コードだけを判定するものではない。 |
| `cyclical_normalization_review` | **循環正常化点検**。利益・CFと景気や商品価格の関係が裏付けられ、足元の入力を正常値として扱う前に点検が必要。期間年数は固定しない。 |
| `young_loss_review` | **youngloss点検**。短い営業履歴、商用化・収益化への移行、損失や資金需要等を基に、経路・再投資・存続の評価が必要。赤字一期だけでは根拠不足。 |
| `needs_data` | 適合判断や選んだモデルの入力に不足・矛盾がある。他の点検ラベルと併存できる。 |

例えば金融構造の根拠が確認できても規制資本の必要入力が欠ける場合、`financial_equity_model_review` と `needs_data` を併記できる。金融機関の収益に循環性が認められる場合、金融と循環の両点検を残す。この例はラベルの使い方であり、特定企業の判定ではない。

`review_assessments` では、各ラベルについて `selected` を `true` / `false` / `null`、`status` を `supported` / `not_supported` / `unassessed` / `conflicted` として記録する。選択した根拠は `supporting_fact_ids`、反対根拠は `counterevidence_fact_ids`、不足は `missing_fact_ids` と `missing_model_input_ids`、説明は `rationale` に保存する。情報不足のため未判定なら `selected: null` のままでよい。

`result.missing_model_inputs` には、`input_id`、必要なモデル、定義・単位・対象期、既に確認したfact ID、不足理由、調べる公開資料の種類を記録する。値が取得済みでも、そのモデルと定義が違えば充足したことにしない。各点検に関係ない入力まで一律に要求しない。

`result.status` は `needs_data`、`research_review_recorded`、`conflicted` のいずれかを使う。`research_review_recorded` は研究上の点検先を記録したことを示し、適正価格・専用計算・投資判断が完成した意味ではない。最終確認者と時刻は `assessed_by` と `assessed_at`、反証点検は `counterreview` に残す。

## モデルの実装状況と禁止する取り違え

現在の評価器は上記5つのmethodに対応する。`eps_multiple` は正のEPSとPER、従来の `dcf` は会社全体の年末アンレバードFCF予測と、現金・負債・株数による株主価値への調整を入力する。この通常DCF欄へ、銀行の株主CFや配当をそのまま入れない。

2026-10-15の実装状況の追補：次は [valuation.py](../src/ir_agent/valuation.py) に実装済みの純計算であり、配当割引を未実装とは扱わない。

- [`dividend_discount`](financial-equity-valuation-spec.md)：明示した将来の年末DPS列と終価翌期DPSを、予測期・安定期の株主資本コストで扱うDDM。会社全体FCF・WACC・現金/負債/株数の調整とは別の1株価値計算である。
- [`dcf_explicit_terminal`](explicit-terminal-fcff-spec.md)：明示した終価翌期FCFFを使う、既存と同じ単一割引率の別method。翌期額へ税・再投資・成長を再適用しない。
- [`dcf_explicit_terminal_equity_bridge`](explicit-equity-bridge-spec.md)：明示終価DCFに、現金・非営業資産・負債・少数持分を分けた株主価値調整を持つ別method。

別の[regulatory-fcfe中間計算](regulatory-fcfe.md)は、明示した年次NIと規制資本再投資を同じ会社/主体/株主/通貨/単位で差し引く。利益と資本の測定定義は別に保持し、資本目標や将来再投資を補完しない。

これらの計算成功は、予測の妥当性、分配の持続性、規制資本、希薄化、簿価/時価・持分範囲や重複排除の確認ではない。各仕様の入力範囲と適用上の不足を別に記録する。旧method・研究ラベル・24項目の事実契約は変更しない。

次は研究方針として必要でも、専用エンジンとして実装済みとはしていない。

- 規制資本の必要/目標/再投資予測の準備、FCFEの終価・株価換算、株主超過収益等の専用処理。DDMやFCFE中間計算を、これらの実装と取り違えない。
- 履歴を取得し、利益・再投資・資本収益・資金調達を整合的に正常化する処理。
- 若い成長企業の売上・利益率の移行、追加資金・希薄化、同じ価値範囲での生存・失敗調整。

既存DCFへ明示した将来CF配列を入力できることは、その配列の妥当性や上述の専用処理まで実装した証拠にはならない。

**金融機関のPERを禁止しない。** 原典は金融機関のPER/PBR比較を扱い、利益成長・配当性向・株主資本コスト、引当や事業構成の差を点検する。金融機関ラベルだけで現在のEPS倍率計算を禁止・採用する規則は作らない。

値動きの小ささ、業界ラベル、損失一期、EPSが正であることだけで、除外・通常モデル・専用モデル・買いを機械的に確定しない。矛盾するラベルの固定優先順位も設けていない。研究用ラベルが既存の会社 `status` を自動更新することはない。

## 記入後の確認

1. 会社の根拠IDと方法の引用IDを取り違えていないか。各引用が原文と指定位置に対応するか。
2. 主体・会計・対象期・単位・実績/予想/仮定を区別できるか。`as_of` 後の情報が混じっていないか。
3. 未確認値が `null` のままか。`false` や `not_applicable` には根拠があるか。
4. 赤字やサイクルの原因に別の説明がないか。複数の点検や `needs_data` を消していないか。
5. 専用モデルの必要入力と、実装済みの範囲を区別しているか。原典の例示数値や推測を既定値へ入れていないか。
6. 点検先と不足を記録した成果を、会社除外・適正価格・売買・送信完了と呼んでいないか。

このテンプレートの利用は、確認済みの外部評価手順を調査へ適応する作業である。方法の採用に追加の利用者回答は必要としないが、外部への問い合わせや注文を実行する権限を与えるものでもない。

## 会社原文で点検した3例

[銀行1社・保険業2社の比較](../research/ir-financial-business-scope-comparison-2026-10-15/README.md)では、5831の金融株主価値モデル研究、7325の保険選択/FC/技術サービス、7157の連結IFRSと日本基準個別配当基準を区別した。銀行の規制資本定義を他の保険業タグへ自動適用せず、会社紹介だけで通常モデルにも確定しない。3例の保存範囲の点検であり、1,819社や金融56社全体の適合判定ではない。
