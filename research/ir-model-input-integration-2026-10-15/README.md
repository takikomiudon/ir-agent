# 数値出典と未設定確率の統合

全911テストが33.617秒で成功した。実行結果は[tests.log](tests.log)、範囲と実台帳の状態は[summary.json](summary.json)に保存。これは観測の分類訂正機能を追加する前のチェックポイントである。

- 確率が未設定なら個別シナリオだけを評価し、期待値を補わない。保有の反証・目標・リスク点検と、期待上昇余地が必要な新規購入を区別する。
- 公表値の逐語引用、数値文字列、単位、期間を保って構造化する。モデル入力の出所を実績・会社予想・外部予想・明示仮定・架空例に分けて点検する。
- 複数の全原典へ遡り、別会社・時点・公開性・架空資料を点検する。埋め込みJSONでも重複キー・非有限値を拒否し、数値照合にDecimalを使う。

[モデル監査例](synthetic-model-input-audit.json)と[確率なしの評価例](synthetic-unweighted-valuation.json)は架空の入力である。数値の出典が一致しても、単位・期間・会計範囲・予測の妥当性を検証したことにはせず、金融入力は未検証を維持する。

[千葉銀行の実資料の抽出](../ir-case-studies-2026-10-15/8331/extraction-notes.md)は年間64.0円、中間32.0円、配当性向0.411を構造化した。将来DPS、資本コスト、確率、評価額への自動採用はしていない。窓口未確認のため1,819社の窓口台帳へ追加せず、この派生資料も実DBへ未登録。

[読み取り専用の実台帳棚卸し](coverage.json)では窓口1,819社、公開資料のある2社20件、仮説0、会社への方針割当0、相場資料0。20資料は分類済みだがモデル入力は未検証。実IR送信・注文は0件。
