# 原文抜粋8例による解釈の点検

固定したキーとの分類一致は **8/8**、case内の引用IDと必要根拠セットの対応も **8/8** だった。[採点結果](trial-1-grade.json)と[回答](trial-1-answers.json)を保存した。親も8件の理由を読み、予定から実施、会社目標から著者閾値、CF表示から正常利益採用などの飛躍をしていないことを確認した。

これは必須運用文書を読んだ担当による、小さな手順再現の点検である。[実行記録](trial-1-execution.json)には、その文書に同題材の説明があったことを記録した。新しい会話コンテキストで、キーや先行チャットは渡していないが、完全な情報隔離・未見データ・一般性能の試験とはしない。ファイルアクセス範囲は担当の申告であり、OSによる隔離ではない。投資成績・予測精度・確率校正も評価していない。

| ケース | 点検した区別 | 固定分類と回答 |
|---|---|---|
| B01 | AND条件の片側と条件全体 | 未確立で一致 |
| B02 | 減損のP/L・営業CF調整の表示事実 | 支持で一致 |
| B03 | その表示と正常営業利益への採用 | 未確立で一致 |
| B04 | 会社EPS予想の旧版と修正版 | 支持で一致 |
| B05 | 取得予定日と実施完了 | 未確立で一致 |
| B06 | 会社の構成比目標と著者の反証閾値 | 未確立で一致 |
| B07 | 億円から百万円への単位算術 | 支持で一致 |
| B08 | 会社NI由来の著者EPS計算と独自NI予測 | 矛盾で一致 |

B01/B03は「抜粋だけで主張全体が支えられるか」という固定範囲で未確立とする。未記載から反対命題を真にしない。B07は37,800という表示算術までで、別資料の37,860との違いの原因を選んだ結果ではない。各例は実際のIR返信や売買判断ではなく、保存済み公開原文から作った教材である。

[入力](input-cases.json)、[キー](answer-key.json)、[原典manifest](source-manifest.json)、[評価手順](evaluation-protocol.md)を分離し、[親の固定記録](root-pretrial-freeze.json)は試行開始前に入力・キーのSHAを保存した。キーは変更していない。[独立キー確認](independent-key-review.md)は試行回答を読まず、8原典・12抜粋と判定の境界を点検した。手作業の文体による手掛かりや共有抜粋があるため、8件を独立した金融性能観測とは数えない。

[採点script](grade-trial-1.py)は分類と引用ID集合を計算する。理由の意味の正しさは別の読取点検であり、文字列一致で証明していない。scriptは既存採点結果の上書きを拒否する単回保存用。キーや回答を後から都合よく変えるための機能ではない。

外部GET・DB操作・production変更・金融予測登録・IR送信・投資条件の採用は0。最後のproduction統合検証1,312件とは別の研究上の点検である。
