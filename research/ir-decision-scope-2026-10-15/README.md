# 確率がない段階で何を判断できるか：原著・実装・未指定条件の分離

**確率付き期待値を全ての研究判断の前提にする要件は、確認した原著にはない。現コードも、確率なしの反証・保有時の評価額到達などを既に扱う。ただし、その手前で完全な数値評価モデル、株価、6項目の方針を一括要求するため、実企業の定性的な論点点検まで同じ関数へ入れようとすると止まる。** この一括要求は本プロジェクトの契約であり、著者が定めた普遍的な順序ではない。

次に行う最小作業は、既存ホクトpreviewの4論点を、公開根拠による支持・反証候補・未解決として再点検すること。previewは既にその研究記録として成立している。新しい汎用API・registry・gateを作る必要はなく、数値投資actionを完成させるために確率や評価倍率を補う必要もない。

本書は保存済み資料の限定研究。GET、DBアクセス、既存ファイル・productionの変更、実企業の数値予測・閾値・確率・送信判断は行っていない。出典の引用・位置・SHAは[source-quotes.json](source-quotes.json)、分類と次タスクは[review.json](review.json)、現コード9例の結果は[code-requirements-repro.json](code-requirements-repro.json)に保存した。

## 公開レーティングは不足する買い条件の代わりにならない

[公開レーティング研究](../published-rating-policies-2026-10-15/README.md)の岩井コスモサンプルは、半年以内のTOPIX相対パフォーマンス予想をA/B+に区分している（PR01/PR02）。その定義文には明示したシナリオ確率はないが、予想の算定方法全体を確認したものではない。「確率付き期待値が全ての著者・評価分類の共通要件」という解釈を裏付ける資料ではない。

同時に、これは2026-04-17付サンプルの部分確認であり、絶対上昇余地、厳密な区間境界、本人の費用/リスク、目標到達時の売却指示を提供しない。TOPIX相対予想を既存 `minimum_upside_pct` に代入したり、ホクトへレーティングを付けたりはできない。利用者の採用済みprofileは0件のまま参照する。新しい外部レポートや未保存の規則は調べていない。

## 現コードが実際に要求するもの

対象は[pure decision](../../src/ir_agent/decision.py)と[thesis検証](../../src/ir_agent/models.py)。保存来歴・公開性訂正・現在株価/仮説版のwrapperを弱める提案はしていない。

1. `validate_thesis` は、非空のpillars・反証条件・evidence、時点、再点検日だけでなく、`valuation` と `current_price_jpy` による計算成功を要求する。これは「定性thesisだけでも同じ保存契約へ登録できる」というAPIではない（CG01）。
2. `decision` は `minimum_upside_pct / maximum_downside_pct / entry_cost_pct / exit_cost_pct / max_quote_age_seconds / target_scenario` の6項目を一括確認し、1つでも未設定なら `policy_not_configured` で戻る（CG02）。買い用最低上昇余地を使わない反証分岐でも同じである。
3. 保有状態・仮説状態・公開性・根拠・期限・全原典・sourceに結合した株価/鮮度を確認し、その後に数値評価を計算する。期限到来は `thesis_review_due` で保留し、反証の退出分岐より先に返る（CG03/CG04）。
4. `aggregation:unweighted` なら期待値を補わない。それでも既に計算できる保存評価と全方針がある場合、反証、目標到達、提示シナリオのリスク制約、保有継続の分岐へ進める。新規購入の最低期待上昇余地だけは計算できず `scenario_probabilities_not_configured` となる（CG05）。
5. 現在の通常 `daily` はactiveかつ利用可能な保存thesisを必要とし、packetへvaluation計算も含める（CG06）。初期資料分類intakeが完了したことと、数値thesisなしのpreview研究がこのdailyへ自動登録されることは別である。

ここでコードが要求するのは数値評価の計算可能性等であり、計算器自体が独立予測の妥当性を検証したことではない。会社予想・外部予想・明示仮定の採否と意味は別に点検する。1期の会社予想があるだけで数値モデルを完成済みにしない。

## 確率なしで成立する点検と、その限界

| 点検 | 根拠があれば判断できること | 追加条件・限界 | 現契約との関係 |
|---|---|---|---|
| 特定論点を支持/弱める新しい公開事実 | 同じ期・範囲の公表値/逐語引用が、事前の事業説明に整合するか。研究を継続するか、比較をやり直すか。 | 全社の仮説成立や利益予想達成とは別。資料未取得/意味不一致なら未解決。 | preview artifactで既に可能。financial actionの`watch`を得るために数値を作らない。 |
| 反証の成立 | 事前に明示した反証条件と公表根拠が一致するなら、該当pillarの説明を採らず研究仮説を再点検できる。 | 記録後に都合のよい反証条件を作らない。会社の定義が分かっただけでは反証成立にならない。 | research上の結論はコード不要。現在の`exit_review`を得るには上記全gatesも必要。 |

## ホクト1379：4つの公開観測条件にどう接続するか

基準は[既存preview](../ir-case-studies-2026-10-15/1379/earnings-preview-candidate.md)と、その[引用付きJSON](../ir-case-studies-2026-10-15/1379/earnings-preview-candidate.json)。以下の検証仮説は**記録者の研究上の解釈**であり、会社が通期予想達成の必要十分条件や感応度として開示したものではない。

| 既存condition ID | 今の公開根拠から既に行える研究判断 | 次の公開資料での支持・反証候補・未解決の扱い |
|---|---|---|
| `domestic-price-demand` | Q1の国内単価好調という会社説明は保存済み。販促/エリア戦略に加え、天候・野菜相場も会社自身が挙げるため、恒久的な価格決定力だけへの帰属は支持できない。 | 同じ品種・期間・比較基準の単価と販売/利益が整合すれば、この説明への支持を追記。単価の失速や販売/国内利益との不整合は持続解釈を弱め再研究。価格の分母/構成や数量が不明なら未解決。買い/売りへ直結しない。 |
| `domestic-production-sales` | 需要予測による生産調整と「ほぼ計画通り」は公表済み。生産計画達成は販売好調・売切り・需要増の証拠にはならず、その推論は採らない。 | 生産・販売/在庫・品質と同じ範囲の説明を突合。公表された在庫/特売/品質問題や生産との不整合は「調整で安定収益」という解釈への反証候補。販売未開示なら生産から補完しない。子会社化/商品範囲差も確認。 |
| `chemical-pricing-cost-supply` | 仕入上昇・出荷制限・価格改定・受注安定というQ1の会社説明を区別して記録できる。改定の実施だけで将来の転嫁率/採算を認定しない。 | 同一セグメントの価格/仕入/供給/数量と利益の説明が整合すれば支持。会社公表の転嫁遅れ・供給難・受注/採算悪化は持続解釈を弱める。寄与が分解できなければ未解決で、転嫁率を作らない。 |
| `costs-versus-comparison-base` | 計画比の販管費抑制と前年比の増減図は別の比較。計画超過を前年比の恒久コスト削減とする解釈は現時点で採用しない。 | 同一範囲の費用/比較基準と時期説明を追記。費用後ずれ・抑制剥落が実際に公表されれば持続解釈を弱める。後ずれ自体は現在未確認なので事実化しない。営業利益から税/特別損益/株数を飛ばしてEPSへ変換しない。 |

この4論点を点検するために、事前確率やPERは必要ない。反証候補を観測しても、基準となる完全な保有thesisや退出規則がない現在は`exit_review`を新たに宣言せず、「どの研究解釈を弱め、何を再照合するか」を記録する。4件の支持を足して通期達成や高い勝率へ変換しない。米国/台湾等の相殺要因も既存previewのまま併記する。

次のカレンダー記載は2026-11-13予定だが、年度見出しに不整合があり、時刻/timezone・実施も未確認。次の確認では実際の公表資料の会社・期・比較範囲を先に確認する。予定到来や未取得を「未発表/期限超過/仮説否定」と扱わない。

| 原著から引き継げる手順 | 公開情報先行、検証可能な仮説、特定pillarへの新情報の影響、反証、定期点検、事業条件と評価入力の対応。 |

## 次の具体的な最小task：コード不要

**既存1379 previewをそのまま基準に、同じ4 condition IDへ次の実際の公開根拠を照合する、会社固有の再点検を行う。** 汎用registry、数値モデル用の新gate、仮のvaluation/価格は追加しない。現段階で同じpreviewの言い換えをもう1本作ることも不要。

1. 本資料に示した現在の結論を研究上の判断として使う：Q1説明の存在は確認、恒久価格力/生産=販売/改定=将来採算/計画比抑制=恒久削減という外挿は採用しない。会社予想への採用・勝率・売買判断は留保する。
2. 新しい正式資料が実際に保存された時に、既存4IDと引用/対象期/比較範囲を対応させ、「支持」「持続解釈への反証候補」「意味/根拠不足で未解決」を旧previewと比較する会社固有の追記artifactを作る。予定日だけで自動実行・結果生成をしない。今回は新GETしない。
3. 公開根拠で説明が解ければIR論点を除く。定義だけ明確になればその説明だけ訂正し、EPS/倍率や退出へ飛ばさない。まだ不明な場合は、どの研究解釈が未確認かを残す。数値入力へ結び付かないまま質問登録のための入力pathを作らない。
4. 数値評価へ進む必要が実際に生じた段階で、会社予想/外部予想/独立仮定を分けて入力採否を検討する。出典付きシナリオがあっても確率がなければ既存unweightedで範囲を計算できるが、ホクトで今それが完成したとはしない。新規買い判定は現契約のまま別途未解決。
