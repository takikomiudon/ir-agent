# Tweedyの価値超過subcase：研究点検の最小設計

**現時点では新evaluatorを実装せず、既存の定性caseと根拠付き研究記録で足りる。** 原典の価格超過subcaseは売却と継続保有理由を点検する候補にできるが、売却必須・完全な売買方針ではない。会社別に採用された本源価値の根拠も未確定のため、専用比較器を先に増やさない。以下は、rootが適用先と必要性を決めるための設計であり、実装・方針採用の承認ではない。

## 原典と適応の境界

保存ADVの物理p8、`research/ir-tweedy-author-policy-discovery-2026-10-15/quotes.json` の `conditional-sale` と `holding-exception` を根拠にする。原PDF SHAは `db4b255e68c5bcec97934d991d1c45aeace87ab7b0f3ea58779253f732bff2d2`、保存text SHAは `397a46f02ed9bcc4f3834c1d32fbfad41619e5a8336e1b0ba3935be6fed73ec1`。前者は市場状況による条件付きの売却可能性、後者は価値増加を見込む場合の継続保有例外を述べる。管理部門案内の物理p3（原SHA `bb123294926352e7055d0a8e76c186302dbc4d007fadc376cd285bb20da77dbd`）も一般的な売却方針と保有理由の例外を述べる。この文書では逐語引用を追加しない。

厳密な `価格 > 推定本源価値` は原典の超過部分を狭く取り出す研究上の適応とする。接近・大幅割安に独自の幅を付けず、等価の場合も接近を自動認定しない。超過がfalseでも未採用の接近条件や別の売却理由を否定できない。本源価値が正しいこと、市場状況が売却に適すること、例外が成立しないことも大小比較からは導けない。

## 既存経路を先に使う

`docs/qualitative-research-jobs.md` のcaseに同一論点を作り、採用した著者条件と会社別の価値仮説・保有継続理由を研究fileへ記録できる。新source又は既存管理日でqueueし、workerが固定packetへ出典・逐語引用・理由を対応させ、未確定ならcase observationをunresolvedとして残す。新しい価格sourceを含めるかは明示的なcase登録範囲で決め、価格だけで全社へjobを増やさない。管理日を売却期限にしない。

`value`は出典付きの明示モデルを計算できるが、計算成功やbase scenarioを本源価値の採用認定にしない。既存`research-decision-review`は固定v1 policy・最新thesis・価格・明示positionを保存する経路であり、今回の部分条件だけを通すために六条件を削除したり、費用や確率を補ったりしない。既存v1がunresolvedならそのまま残す。定性completeの結果をv1計算済みactionやresearch-decision-reviewへ代入しない。

## 別の研究レポートが必要になった場合の最小入力

これは候補契約であり、新CLI・table・schemaを今追加する提案ではない。値を直接受け取る比較器ではなく、保存記録を参照する必要がある。

| 入力 | 必要な参照・宣言と未検証範囲 |
|---|---|
| 適用対象・著者条件 | company ID、証券/株式クラス、論点ID、原典source ID/版/SHA/位置、採用者・適用理由・固定研究版。著者自身が当該日本株を評価したという意味にしない。 |
| 価格 | source-bound quoteの元数値・観測時刻・取得時刻・source/全原典参照。既存JPY契約の対象外通貨へ暗黙に拡張しない。別市場/株式クラス/分割前後を同一視しない。 |
| 推定本源価値 | 誰のどの評価か、単一の明示額とsource又は計算来歴/モデル版/入力/出典。目標株価、相対レーティング、企業価値、簿価を自動代用しない。複数scenarioからbase等を自動選択せず、rangeの端・中点を補わない。 |
| 比較basis | 同会社・同証券/株式クラス・同通貨・一株当たりの同単位・分割調整基準を明示。既存company_idだけでは株式同一性を認証できない。FX、株数換算や企業価値から株主価値への変換をこのレポートで補わない。 |
| 評価の時点 | 評価基準日、予測の対象期間、記録/取得/公表時刻、対象価格時点にその評価を用いる理由、更新/失効状況。単なる最新保存版や古い著者目標をcurrent認定しない。適合のレビュー担当・根拠を残し、独自の有効日数を作らない。 |
| 保有と裁量事項 | 明示position receiptのheld true/false/unknown、確認時点。売却に適する市場状況、価値増加見通し/保有継続理由は根拠付きの担当者評価とunknownを区別する。無入力をfalseや例外なしへ変えない。 |

原source DAG・SHA・会社・availability・公開性・訂正/依存IR holdは既存機能を狭く再利用する。これらの通過は元サイト真正性、証券同一性、本源価値の意味・妥当性の独立認証ではない。意味の採用と来歴の機械検査を別fieldにする。現在のJPY quoteやcompany-level thesisで足りない証券同一性・本源価値の採用来歴を、架空metadataで埋めない。

## 比較とoutputの区分

根拠と意味の採用が揃った明示値だけを、既存Decimalの規約で厳密比較する。費用・確率・期間・相対上昇率は算出しない。出力は研究報告であり、既存action列挙値を返さない。

| 状態 | 報告する内容 |
|---|---|
| 構造不正・比較矛盾 | 別会社/証券、壊れたbinding、不正数値/単位等はinvalidとして比較を行わない。単に条件未達とはしない。 |
| 必要情報が未知・古い | 価格又は本源価値の未取得、意味未採用、評価時点の適合未確認、source hold等はunknown。どの前提が不足かを返す。 |
| 有効な比較で価格が上回る | 超過条件の一致と、売却可否・価値増加/継続理由の点検対象であることだけを記録。強制exit、v1のexit_review、例外なしにはしない。 |
| 保有true | 超過条件が一致すれば、当該保有について売却/継続理由を点検する候補。ただし市場状況・例外は独立にunknown又は根拠付き評価を残す。 |
| 保有false / unknown | falseは保有からの売却点検に不適用。unknownは保有確認が必要。数値関係が既知でも、保有の前提を推定しない。 |
| 価格が等しい/下回る | この厳密な超過subcaseは不一致。保有推奨・新規購入・接近条件の不成立・他の売却理由なしを意味しない。 |

必要ならreportには、対象時刻・実作成時刻、rule/研究版、価格と価値の原token/各basis、source ID/SHA/位置、position版、strict比較結果、各前提の状態、担当者の意味レビューと未解決理由を含める。元結果を不変にし、価格失効・新価値版・position変更・source訂正時は現在利用可否を別表示する。更新前の値を現時点へ繰り越さず、過去unknownを表示だけで成立へ昇格させない。

## 実装を検討する条件

既存caseで扱いきれない量の**採用済み・出典付き本源価値と同一証券の現在価格**が実際に揃い、根拠の意味/時点/例外を版固定して繰り返し点検する必要が生じた場合だけ、rootが狭いread-only研究reportを検討する。その価値は数値の大小そのものではなく、原文から評価額への意味の誤昇格と、古い評価・不明な保有・例外欠落を防いで再現可能にすることにある。今回、具体的な適用会社や不足を埋める入力を作成していないため、その必要性は未実証であり、新evaluatorは不要とする。

実施範囲：保存原典と既存docs/decision実装の読取のみ。新GET・実DB操作・src/tests/共用docs変更は0。このREADMEだけを新規保存した。
